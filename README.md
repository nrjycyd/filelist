# vitepress-plugin-filelist

OpenList file browser for VitePress — tree view, batch ZIP download, folder password and token support.

VitePress 的 OpenList 文件浏览组件：树形展开、勾选批量打包、目录密码、token，直接调用 OpenList 接口。

## Features

- 📁 Tree view with lazy-loaded folders
- ✅ Checkbox selection, folder selects its loaded children
- 📦 Batch download as ZIP (via `fflate`), with progress
- ⬇️ Single file download and preview (`/d/`, `/p/`, `fs/get` raw URL)
- 🔐 Folder password prompt, optional read-only token
- 🔎 Filter current tree, sortable name / size / date
- 🌐 Uses `/api/fs/list`, `/api/fs/get`, `/api/public/settings`
- 🧪 Demo mode with built-in fake data when `base` is empty
- SSR safe (network requests only run on the client)

## Install

```bash
pnpm add -D vitepress-plugin-filelist
# or: npm i -D vitepress-plugin-filelist
```

## Usage with vitepress-tuck

```ts
// .vitepress/config.ts
import { defineConfig } from 'vitepress-tuck'
import fileList from 'vitepress-plugin-filelist'

export default defineConfig({
  plugins: [fileList()],
})
```

## Props

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `base` | `string` | `''` | OpenList base URL. Empty = demo mode |
| `path` | `string` | `'/'` | Initial directory |
| `token` | `string` | `''` | Optional read-only token (guest when omitted) |
| `password` | `string` | `''` | Folder password; can also be entered at runtime |
| `title` | `string` | `''` | Toolbar title; falls back to OpenList `site_title` |
| `locale` | `'zh-CN' \| 'en-US'` | `'zh-CN'` | Built-in label preset |
| `labels` | `Partial<FileListLabels>` | `undefined` | Per-key label overrides |

Both `<FileList>` and `<VPFileList>` are registered.

## i18n

```md
<FileList locale="en-US" base="https://pan.example.com" />
```

Override individual labels on top of the preset:

```md
<FileList
  :labels="{ batch: '下载全部', loaded: '共 {count} 个文件' }"
  base="https://pan.example.com"
/>
```

Available presets: `zh-CN`, `en-US`. Placeholders use `{count}`, `{percent}`, `{message}`, `{name}` and are replaced by `formatLabel()`. The full key list is exported as `FileListLabels`:

```ts
import type { FileListLabels } from 'vitepress-plugin-filelist/client'
import { fileListLocales, formatLabel, resolveLabels } from 'vitepress-plugin-filelist/client'
```

## OpenList requirements

1. **Guest read access** — enable the guest user, or pass a read-only `token`.
2. **CORS** — OpenList's `cors.allow_origins` must include your site origin (default `*`).
3. **Same protocol** — an HTTPS page cannot call an HTTP OpenList (mixed content).
4. **Token is public** — only ship a read-only token that can be revoked.

The component calls:

| Endpoint | Purpose |
| --- | --- |
| `POST /api/fs/list` | Directory listing (`per_page: 0`) |
| `POST /api/fs/get` | `raw_url` for download / preview / ZIP; falls back to `/d/...?sign=` |
| `GET /api/public/settings` | `site_title` fallback |
| `GET /d/...` `GET /p/...` | Download / preview links generated by OpenList |

## Compatibility

Peer dependency allows VitePress 1.x and 2.0 alpha: `^1.0.0 || ^2.0.0-alpha.0`.

Tested locally against VitePress `2.0.0-alpha.21` on Node 22:

| Package manager | Install | Build |
| --- | --- | --- |
| npm 10 | ✅ | ✅ |
| pnpm 11.25 | ✅ | ✅ |
| yarn 1.22 (classic) | ✅ | ✅ |
| bun 1.4 | ✅ | ✅ |
| deno 2.9 | ✅ `deno install` | ❌ fails while Vite/rolldown loads the config |

Deno can install the npm dependency, but building a VitePress site with Deno currently fails inside rolldown (`stream did not contain valid UTF-8`). Use Node for builds.

## Notes

- Batch ZIP downloads files through `raw_url` (OpenList `/p/` proxy), which keeps CORS on the OpenList origin.
- Select-all only counts already-loaded files; the footer reports how many folders are still collapsed.
- Directory listings are requested with `per_page: 0` (all entries). Very large folders may be slow; pagination is not implemented yet.
